# 开发约定

## 用例表达

API 定义具体 HTTP 方法/路径和 WS 指令/请求结构，用例及关联流程调用 API 展示业务步骤，数据和脚本分目录。API 只返回响应，不自动断言业务成功或拦截待测输入，不隐藏状态等待/查询闭环。复杂且确实重复的断言才抽取。

公共通信不导入 API；前后置辅助 common/setup.py 可以通过 API 登录、核对设备和恢复状态。业务准备检查属于 fixture，不属于 API 的成功断言。

## 中文注释

- 普通 # 注释若前一行是代码，之间留一行空行；注释紧挨解释的后续代码。
- 函数/类说明使用三引号，结束后空一行再写代码。
- with/async with 块内说明使用三引号，结束后空一行；它是块内说明字符串，不是 Python 函数文档字符串。
- 不把注释接在代码行尾。

## 通信与状态

HTTP 不自动断言状态码或业务字段。WS 不预先拒绝待测业务参数，业务拒绝原样交给 case。

每连接一个 reader，发送前游标、共享历史和条件等待；业务心跳与协议 Ping/Pong 分开。请求串行，控制结果不确定不重放；恢复失败不吞异常，资源关闭仍继续。

同接口 module scope 连接必须匹配 module loop_scope。断线/身份切换测试使用独立资源，不能破坏普通 case 的共享连接。

## 数据与凭据

数据层只检查分组、唯一 id、request/expected 对象。负数、小数、空值、字符串均可作为测试输入。实际协议预期未确认的不作为正式通过/失败 case。

凭据只从环境变量取得；headers/cookies/body/URL 日志脱敏。环境选择不改变测试预期，不再接受 IOT_HDMI_VOLUME 隐藏覆盖。

## 验证

```powershell
.\run-tests.ps1
.\.venv\Scripts\python.exe -X dev -m pytest --asyncio-debug -q
.\.venv\Scripts\python.exe -m pip check
```

完整回归包含故意失败的独立 pytest 探针，外层验证其恢复、报错和关闭行为，因此正常完整结果应通过。所有重构验证默认本地模拟，禁止把模拟结论写成真机边界或物理执行结论。
